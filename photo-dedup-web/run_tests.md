# run_tests.md — 手工验收清单

建议先用一个小目录复制真实文件测试。

## 准备测试目录

```
test_root/
├── photo/                 # 同目录像素相同的 3 份（改过 EXIF 使大小不同）
│   ├── 2023-05-04_12-30-15.jpg
│   ├── keep.jpg
│   └── IMG_0001.JPG
├── backupA/
│   └── clip.mp4           # 与 backupB 的文件字节相同
├── backupB/
│   └── clip_dup.mp4
└── unique.png             # 唯一文件，不应成组
```

> 3 张 jpg 可先复制同一张图片，再对其中一份用任何工具修改 EXIF / 另存为不同扩展名。

## 验收步骤

1. `cd photo-dedup-web && pip install -r requirements.txt && python run.py`
   → 浏览器自动打开 `http://127.0.0.1:8000`，出现带输入框的页面。

2. 输入 `test_root` 绝对路径，点「开始检查」。
   - 观察进度条阶段变化（counting → 图片指纹 → MD5 → 完成）。
   - 完成统计：重复组 2；图片组显示 3 份、视频组显示 2 份。
   - 图片组默认保留：`2023-05-04_12-30-15.jpg`（含日期+时间，得分最高）。

3. 点击图片组表头展开：显示 3 行，每行左缩略图、中文件名+完整路径、右大小/类型，
   最右单选「保留（⊙）/ 待移动（○）」；保留项绿标签、待移动项红标签。

4. 把某一行改为「保留」，点「移动到 temp（释出清单）」
   → 出现 dry 预览列表（这 N 个将移动），点「确认移动」。
   - 图片组源目录只剩你保留的那 1 份；其余文件移到 `test_root/.photo_dup_removed/同名相对路径`。
   - 视频组 source 只留 1 份。任何文件都**未删除**。

5. 检查 `test_root/.photo_dup_removed/.moved.log`：每行 `源\t目标`。
   - 手动把某一份从 `.photo_dup_removed` 移回源位置，再次「移动到 temp」→ 预览对应项变黄「目标存在·跳过」（不覆盖）。

6. 再次点「开始检查」同目录 → 命中缓存，秒级返回，且已移走的文件不再计入重复（`groups=0`）。

7. 输入不存在的路径点开始 → 页面 toast 报错，不崩溃。

8. 扫描进行中点击「取消」→ 任务被取消，页面回到可重新扫描状态。

## 覆盖的异常分支（代码已实现）

- 损坏/无法解码的图片 → 该项指纹为不可用、跳过，不影响整体。
- 目标已存在 → `skip`，不覆盖。
- 源文件不存在 → `failed`，不覆盖。
- 重复提交扫描 / 目标路径非目录 / 空路径 → 后端返回可读错误。
- 上万文件：分页渲染（默认每页 60 组）+ 缩略图懒加载，避免 DOM 卡死。
